# API guide

Base URL: `http://localhost:8000/api/v1`. Interactive documentation: `/docs`, `/redoc`, `/docs/en`, `/docs/ru`, `/docs/kk`. Localized schemas: `/openapi/en.json`, `/openapi/ru.json`, `/openapi/kk.json`.

Register with a unique username (2–100 characters), valid email and password (8–128 characters):

```http
POST /api/v1/auth/register
Content-Type: application/json

{"username":"yourname","email":"you@example.com","password":"choose-a-unique-password","preferred_language":"en"}
```

Sign in using `POST /auth/login` with `email` and `password`. Its envelope contains `data.access_token`. Add `Authorization: Bearer <access_token>` to authenticated requests.

```http
POST /api/v1/projects?lang=kk
Authorization: Bearer <access_token>
Content-Type: application/json

{"name":"Website launch","description":"Plan our next release"}
```

The response is HTTP 201 with `code: PROJECT_CREATED`, `message: Жоба сәтті құрылды`, and `data` containing the project. Resource IDs and timestamps are generated by the database/application.

| Resource | Methods |
|---|---|
| `/users/me` | GET |
| `/users/me/preferences` | PATCH (`preferred_language`) |
| `/users/me/tasks` | GET |
| `/projects` | GET, POST |
| `/projects/{project_id}` | GET, PATCH, DELETE |
| `/projects/{project_id}/members` | GET, POST (`email`, `role`) |
| `/projects/{project_id}/members/{user_id}` | PATCH (`role`), DELETE |
| `/projects/{project_id}/tasks` | GET, POST |
| `/projects/{project_id}/tasks/{task_id}` | GET, PATCH, DELETE |
| `/dashboard/summary` | GET |

Task input: `title`, `description`, `assigned_to_id` (nullable), `status` (`TODO`, `IN_PROGRESS`, `DONE`), `priority` (`LOW`, `MEDIUM`, `HIGH`, `URGENT`), `due_date` (nullable ISO 8601 with zone). PATCH sends only changed fields; null is accepted only for assignee and deadline.

Task list filters: `search`, `status`, `priority`, `assigned_to_id`, `due_before`, `due_after`, `page`, `page_size`, `sort`, `direction`. Sort fields: `title`, `created_at`, `updated_at`, `due_date`, `priority`, `status`; direction: `asc` or `desc`. Project lists support `search`, `page`, `page_size`, `sort` (`name`, `created_at`, `updated_at`) and `direction`. Priority sorting follows enum label order in v1. Null deadlines sort last. Board pagination applies across all three columns; column counts describe the current page.

Errors use 400 (invalid assignment), 401 (authentication), 403 (permission), 404 (missing/inaccessible), 409 (conflict), 422 (validation), and 500 (safe internal error). Clients should use stable `code` values and translate them rather than parse human messages.
